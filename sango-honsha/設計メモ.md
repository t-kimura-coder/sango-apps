# 山郷サポート 本社（依頼の進捗・請求）設計メモ

- 山郷のリーダーが送った「対応の依頼」（`kind: request`）を、本社（木村）が、業者への手配と山郷への請求まで管理する画面。使う人は木村だけ。
- データは窓口（GAS）の `honshaList` / `honshaSave` だけを使う。**本社用の合言葉**（`config.local.json` の honshaToken）でしか使えない。山郷側の管理用の合言葉では使えず、管理用の `list` の返事にも本社の項目（金額・手配先）は含まれない（窓口側で確認済み）。
- 本社の管理データは、窓口のスプレッドシートの「本社」シートに、依頼のIDごとに1行（手配先・進捗・手配日・見積番号・業者への支払い・請求額・請求月・請求済み・メモ）。
- 進捗：未手配 → 手配済み → 施工待ち → 施工完了。請求待ち＝施工完了で、まだ請求済みでない。請求済みにするには請求月が必要。粗利＝請求額 − 業者への支払い。
- 画面：依頼（一覧・絞り込み・詳細）／請求（請求待ち・月ごとの集計・CSV）／設定（窓口URL・本社用の合言葉・更新者の名前）。45秒おきに自動更新。入力中の画面（詳細・設定）は自動更新で描き直さない。
- 請求書そのものは、見積アプリのPDFで社内処理する（この画面は請求の「管理」だけ）。

## v24（2026-10-21）：業者の「直接連絡OK（解禁）」を本社が管理（未公開・窓口は未 deploy）
- 背景：リーダー画面 v51 で、業者データの `companies[].direct` が false の業者は「本社経由」（番号を押すと注意と「本社に電話」「症例で対応を依頼」）。解禁の判断は本社（木村）。目安は「本社経由で1回以上手配・施工完了」かつ「業者に山郷から直接連絡がいくことを伝えて了承（請求の流れも確認）」。
- 画面「業者」（`#/vendors`）：本社経由の業者ごとに、本社経由で手配した件数・施工完了の件数（依頼の「手配先」と進捗から数える。名前は全角半角・空白・株式会社/(株)を無視して比べる）と、担当の建物・分類。施工完了が1件以上なら「解禁できます」。「直接連絡OKにする」→ 2つの確認にチェック → 窓口 `masterSetDirect` で切り替え。直接連絡OKの業者は「本社経由に戻す」で戻せる。
- 依頼の詳細：手配先（候補の業者・手入力）が本社経由の業者なら、手配の欄に案内（実績なし＝「初回です。完了したら、業者に『今後は山郷から直接連絡がいく』と伝えて了承をもらってください」／施工完了あり＝「業者の画面で直接連絡OKにできます」）。候補の業者に「本社経由」の印。
- 窓口（GAS）：`masterSetDirect { name, direct }`（`honsha` の役割＝本社・設計者だけ）。業者データの同じ名前の業者すべての direct を切り替え、Drive の業者データを書き直して `master_meta.updated` を新しくする（リーダーのアプリは次に開いた時に受け取り直す）。本社の画面が業者データを読めるように、`masterInfo` / `masterGet` も `honsha` に開けた。
- 元データ（`csv/vendor_phones.csv` の direct 列）との食い違い：**窓口の判断を正**にする。本社の判断はスクリプトのプロパティ `master_direct`（名前ごと {direct, at, by}）に残り、`masterPut`（put_master.js）で csv から作った業者データを置き直しても、その判断を当て直す（解禁が戻らない）。csv と違った業者は `direct_kept` で返り、put_master.js が「direct 列に 1 を入れてください」と表示するので、その時に csv を直す。

## v32（2026-11-16）：山郷への返事を「経過」に（管理者 v48・リーダー v61・窓口 @35）

## 続きの依頼（2026-11-18 v37）
- 背景：宇の建具の依頼で、補修（依頼の中身）は済んだが、その時に扉の別の傷が見つかり、扉の交換の見積が続いている。一本道の進み具合では「完了したが続きがある」を表せない（工事事務の問い。相談窓口のセッションから）。
- Claude の提案：元の依頼は施工完了にし、本社から「続きの依頼」を立てて parent_id でつなぐ（請求も別々）。ほかの案（1件のまま「続きあり」／ひとことだけ）は、請求が混ざる・一覧から消えるので選ばない。→ 決定（工事事務）：その案で作る。
- 窓口：honshaFollow { parent_id, what, urgent, close_parent }（本社）。症例の parent_id 列。建物・分類・場所を引き継ぎ、送った人は「本社」、依頼のメールは送らない。requestStatus に、元の依頼には follows、続きの依頼には parent を付ける。
- 画面：依頼の内容の下に「関連する依頼」（元の依頼・続きの依頼へのリンクと進み具合）と「＋続きの依頼を立てる」（元の依頼を施工完了にするか選べる。初めはチェック）。
