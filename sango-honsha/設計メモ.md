# 山郷サポート 本社（依頼の進捗・請求）設計メモ

- 山郷のリーダーが送った「対応の依頼」（`kind: request`）を、本社（木村）が、業者への手配と山郷への請求まで管理する画面。使う人は木村だけ。
- データは窓口（GAS）の `honshaList` / `honshaSave` だけを使う。**本社用の合言葉**（`config.local.json` の honshaToken）でしか使えない。山郷側の管理用の合言葉では使えず、管理用の `list` の返事にも本社の項目（金額・手配先）は含まれない（窓口側で確認済み）。
- 本社の管理データは、窓口のスプレッドシートの「本社」シートに、依頼のIDごとに1行（手配先・進捗・手配日・見積番号・業者への支払い・請求額・請求月・請求済み・メモ）。
- 進捗：未手配 → 手配済み → 施工待ち → 施工完了。請求待ち＝施工完了で、まだ請求済みでない。請求済みにするには請求月が必要。粗利＝請求額 − 業者への支払い。
- 画面：依頼（一覧・絞り込み・詳細）／請求（請求待ち・月ごとの集計・CSV）／設定（窓口URL・本社用の合言葉・更新者の名前）。45秒おきに自動更新。入力中の画面（詳細・設定）は自動更新で描き直さない。
- 請求書そのものは、見積アプリのPDFで社内処理する（この画面は請求の「管理」だけ）。

## 合言葉（人ごと）（2026-10-12 v2）
- 窓口のURLは、アプリに入っている。設定には、自分の合言葉だけを入れる。`ping` の `caps` に honsha がある合言葉（本社・設計者）だけが使える。

## v4（2026-10-12）：絵・数字・手配の帯・業者の候補・新着・使い方・更新
- 絵：山郷サポートの建物・分類の絵（`art/bld-*.webp`・`cat-*.webp`・`hero.webp`・`logo.webp`。管理者ビューアと同じもの）を、一覧のカード・詳細の上の帯・ヘッダー・空の表示に使う（無い絵は出さない）。
- 一覧の上に4つの数字（未手配／進行中／請求待ち＋合計額／今月の請求＋粗利）。押すと、その状態に絞る。建物での絞り込みも追加。
- 詳細：手配の帯（依頼を受けた→手配済み→施工待ち→施工完了→請求済み）。**この建物・分類の担当業者**（業者データ。電話つき）を出し、名前を押すと「手配先」に入る（設計者の合言葉なら、窓口から業者データを受け取れる。受け取れなくても使える）。
- **新着**：開いていない依頼に「新着」の印と、ブラウザのタブ名に件数（初めて開いた時は、今までの依頼を新着にしない）。
- 請求：月ごとの棒グラフ（請求額と粗利）。使い方のページ。設定の「更新」（データ／アプリ本体）。

## v5（2026-10-12）：敷地マップがメイン画面
- 山郷の公式サイトの敷地イラストマップ（`art/sitemap.svg`、viewBox 891.396×527.086）を、ホーム（`#/map`）に出し、建物の位置（`BLDS`、viewBox の座標）にボタンを重ねた。建物を押すと、その建物の画面（`#/b/<id>`：建物の絵の帯＋その建物の依頼）。マップに無い建物（店舗バックヤード・外構）は、下の建物の一覧から。
- 建物の色＝いちばん急ぐ状態（未手配＝オレンジ、請求待ち＝黄土、進行中＝紺）、右上の数字＝対応が必要な依頼の数、新着はふちが脈打つ、急ぎは赤いふち。上に、4つの数字と、「いま手配が必要な依頼」。
- うまくいったら、リーダー・管理者の画面にも、同じマップを広げる（建物選びをマップから）案。
