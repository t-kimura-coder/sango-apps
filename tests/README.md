# 動作テスト（現場ナビ・見守り）

アプリを見えないブラウザ（iPhone の画面の大きさ）で動かして、決まった手順が今までどおり動くかを確かめる。

## 動かし方

```
cd tests
npm install          # 初回だけ
npx playwright test  # 全部（30秒ほど）
```

- 木村さんの PC では、入っている Chrome を使う。
- クラウドなど Chrome が無い所では `npx playwright install chromium` のあと、`TEST_BROWSER=chromium npx playwright test`。
- 結果は画面のほか `test-results/results.json` に残る。落ちたテストは、同じフォルダに画面の写真と記録（trace）が残る。

## 決まり

- **本物の GAS には何も届かない**。`fixtures/fake-gas.js` が GAS のふりをする（Box の受け口・マニュアルの配布も偽物）。テストの合言葉も作りもの。
- **本物のマニュアル・現場・お客様のデータは入れない**（このリポジトリは公開されている）。マニュアルは `fixtures/fake-manual.js` の作りもの。
- テストはアプリの中身（`app.js`）を変えない。アプリを直したら、ここも直すかを考える。
- 不具合を直した時は、その不具合を再現するテストを足す（同じ不具合がまた起きたら気づけるように）。

## 中身

| ファイル | 確かめていること |
|---|---|
| `specs/genba-manual.basic.spec.js` | 開く・エラーが無い／合言葉でマニュアルを受け取る／検索（項目名・チェックの文・ひらがな・言い換え）／現場の登録（工事番号は大文字） |
| `specs/genba-manual.report.spec.js` | 週の報告を Box へ送る：報告 JSON の中身（schema 8・お客様向けの印・項目名・チェックの固定番号・お客様向けの材料・上司へのメモ）、写真の名前がそろう、送ったあとの報告済み・お客様向けの番号、取り消して送り直すと同じ report_id |
