# 現場ナビ 設計メモ（旧称：現場写真メモ）

## 位置づけ（2026-09-30 方針変更）
- **マニュアルアプリが本体**。起動画面はマニュアル（17分類 → 104項目 → PDFページ）。純粋に監督の作業補助として使える
- その中の機能として「写真・報告」：工程ごとに撮りだめ → 報告用を選ぶ → Boxへメール送信
- 報告メールの文章作成はアプリの外。Boxに届いた写真＋JSON、別途用意するメール用の辞書を材料に、AIとの**対話**で作る
- 窓口は当面Box（本人が被験者として試してから決める）。GAS・スプレッドシート案は保留

依頼書・マニュアルPDF・変換スクリプト（社内データ側）：`工事部業務改善/現場訪問マニュアルアプリ/`（このリポジトリの外）／構成の元ネタ：`工事部業務改善/走行距離/app/技術資料_PWA設計メモ.md`

## 構成
- iPhone専用のPWA（HTML/CSS/vanilla JS、サーバーなし）。データはIndexedDB `genba-photo` に保存
  - `sites`：現場（name, processes=今回の工程IDの配列, lastReportEnd=前回報告の終了日, archived）
  - `photos`：写真（siteId, processId, dateKey, takenAt, blob=長辺1600px, thumb=長辺360px, reportId）
  - `reports`：報告（siteId, start, end）
- **社内データはアプリ（git・公開先）に載せない**（走行距離アプリと同じ方針）。公開するのは仕組みだけ
- マニュアルは「マニュアルパック」JSON1本で配布：`現場訪問マニュアルアプリ/tools/build_manual.py` がPDFから `manual_pack/マニュアル_<版>.json`（約28MB。items=項目と17分類の対応、pages=ページ画像、guides=撮影ガイド）を作る → Boxに置く → 各iPhoneで初回に取り込み、IndexedDB（`meta` / `manualPages`）に保存
  - 振り分けを直すときは同スクリプトの `ITEMS` を編集して再実行（空白ページは直前項目の図・写真ページとして同じ項目に含める）
  - 撮影ガイドの文面は `tools/guides.json`（`{"p02": "…"}`）に書いてパックに同梱。**文面は別途相談して決める**
  - 改訂時は新しい版を作って取り込み直すと差し替わる（写真データには影響しない）
- 17分類の名前は写真機能で使うため `app.js` の `PROCESSES` に持つ（guideはパック取り込み時に上書き）
- ローカル確認：統合システムの `.claude/launch.json` の `genba-photo`（ポート8937）

## 報告期間の考え方
- 写真は「週」ではなく**撮影日**を持つ。未報告（reportIdなし）の写真がすべて「今回の報告」
- 今回の開始日 = 前回報告の終了日の翌日（初回は現場登録日。より古い写真を取り込んだらその日まで遡る）
- 「報告済みにする」で最終日を選ぶ（既定は今日）→ その日までの写真に reportId を付け、次回は翌日から
- 休工で2週分になっても特別な操作は不要（開始日が前回報告の翌日のままなので自然に延びる）。2週以上ならホームに「N週分」を表示
- 金・土曜で未報告の写真がある現場には、ホームで「報告日」を表示

## 撮影まわり
- カメラ：`capture="environment"` で1枚ずつ。撮影後に③画面で「もう1枚撮る」を最大ボタンに
- ライブラリ取込：`multiple` でまとめて。撮影日時は**縮小前**にEXIF（DateTimeOriginal）から読み、なければ lastModified
- 工程はカードの撮影ボタンで決まる（タグ付けの手間なし）。工程は次回の報告に持ち越し、不要になったら✕で外す
- 書き出し：選択した写真を `navigator.share({files})` で共有シートへ（メール添付／「画像を保存」でカメラロール）。ファイル名は `現場名_工程略称_MMDD_連番.jpg`
- 報告済みの写真は自動では消さない。過去の報告から手動で削除

## Boxへの送信
- ④報告まとめ →「Boxへ送信」→ 内容確認＋メモ（任意）→ 宛先アドレスをクリップボードにコピーして共有シート → メールで送信
- 添付：`報告_現場名_開始日_終了日.json` ＋ 選んだ写真。JSONの中身：site / period / sender / memo / processes（工程ごとの撮影枚数・選択枚数）/ photos（ファイル名・工程・撮影日）
- 写真合計15MB超で警告（メール容量対策）。送信後に「報告済みにしますか？」を確認
- JSON schema 2：`checks`＝期間中に付けたチェック（項目・工程・各チェックの文・日時・誰が・写真要か・記録写真の有無、該当なし）。AIとの対話と将来の品質管理の材料
- 写真の工程の付け替え：報告の写真一覧で選んで「工程を変更」、または長押しの画面から
- 初回起動時に名前の登録を1回だけ案内（「あとで」なら以後は出さない。設定で変更可）
- 設定タブで氏名とBoxのアップロード用メールアドレスを登録

## 更新ルール
- **機能追加・不具合修正のたびに `app.js` 先頭の `ANNOUNCEMENTS` に `{date, type: "feature"|"fix", text}` を先頭へ追記する**（ホーム右上のベルに未読の印が出る。自動では増えない）
- 使い方ページ（`index.html` の `helpView`）は操作の流れが変わったら書き直す
- `app.js` / `style.css` を変えたら `index.html` の `?v=` と `APP_VERSION` を上げる
- キャッシュ対象を変えたら `service-worker.js` の `CACHE_VERSION` と `APP_SHELL` の `?v=` も合わせる

## 画面構成（2026-09-30 GPTモック「現場ナビ」に寄せて改修）
- 下タブ：ホーム / 工程 / 写真 / 報告。ホーム右上に使い方（？）・お知らせ（ベル）・設定（歯車）。工程・報告タブは歯車のみ
- ホーム：工程から探す（6つの大分類カード）・今週の報告・写真整理・前回の続き（最近見たマニュアル項目3件、localStorage）
- 工程：6つの大分類（`GROUPS`：基礎=p01,p02 / 上棟=p03,p04,p05 / 外装=p06,p09,p14 / 内装=p07,p08,p11,p12,p13 / 設備=p10 / 引渡し=p15,p16,p17）→ 工程マニュアル画面（ステッパー・17分類ごとの項目一覧・「撮る」）→ PDFページ
- 写真：現場一覧 → 現場画面（工程カードから撮影）→ 撮影直後
- 報告：現場一覧 → 写真を選ぶ（工程チップで絞り込み、選択数、Boxへ送信）
- 工程マニュアル画面（2026-10-01）：大分類ごとに項目を横スクロールで選び、タブで「チェックポイント（概要・ポイント/ゴール・チェック項目・参考図・関連資料[準備中]）」「作業手順（前後の工程・タイミング・事前準備）」「参考資料（PDF原本）」。下に前後の項目（大分類をまたいで移動）
  - 文章は `現場訪問マニュアルアプリ/tools/extract_manual_text.py` がPDFから抜き出し（見出しの揺れ吸収・写真要/不要・追記日付の分離）、`build_manual.py` がパックの items[].text に同梱（schema 2）。手直しは `tools/manual_text_fix.json`
  - チェック記録：IndexedDB `checks`（key=`現場ID|項目ID`、marks=`区分|チェック文`→{at, by}、na=該当なし）。チェックした人（設定の氏名）と日時を残す＝将来の品質管理・育成指標用。現場の選択は localStorage
  - マニュアルから撮った場合、撮影後は工程マニュアルに戻る（shotFrom）
- 写真の2種類（2026-10-01）：photos.kind = "report"（お客様向け。工程カード・工程マニュアル右上のカメラ。種別なしの古い写真もこちら）/ "record"（マニュアルが求める記録写真。「写真要」チェック横のカメラ、itemId・checkKey付き、撮り直しは前の1枚と入れ替え）。報告の画面・枚数（unreported）は report のみ。記録写真の社内向け送信は今後の運用次第
  - 撮影メモ：`現場訪問マニュアルアプリ/tools/guides.json` に {"pXX": {"record": "...", "report": "..."}, "_reportNote": "..."}。記録＝緑ラベル（マニュアル由来、指定なしは空）、報告＝木の色ラベル＋共通注意（ゴミ・工具を写さない）
  - チェックは行単位で描き直す（refreshCheckRow）。全体を描き直したり scrollIntoView を使うと画面が上に飛ぶ
- Box宛先：`app.js` の `BOX_UPLOAD_EMAIL` に書くと固定表示（アップロード専用なので公開で問題ない判断）。空なら設定で入力。コピーボタンあり
- 会社ロゴ（2026-10-01）：社内データなのでアプリ本体には持たない。`現場訪問マニュアルアプリ/tools/branding/`（logo-mark.png・logo-text.png＝黒の透過PNG、branding.json の company）をパック schema 4 の `branding` に同梱 → ホーム最下部「提供」と設定の「このアプリについて」に表示。マニュアル未取り込みの端末・公開ページには出ない。ダークモードは CSS の invert で白にする
- 工程の検索（2026-10-01）：ホーム・工程タブの検索欄 → `searchView`。項目名(重10)・工程番号・分類名・概要・ポイント/ゴール・チェック・事前準備から探す。ひらがな/カタカナ・全角/半角・記号・長音を無視して照合（normText）。スペース区切りはAND
  - 言い換え辞書は社内データ側の `現場訪問マニュアルアプリ/tools/synonyms.json`（`[["上棟","建て方","建方"], ...]`）→ パック schema 3 の `synonyms`。言い換えで当たったものは入力語そのままの一致より下に並べる
- イラスト：GPT生成の透過画像を余白カット・長辺300px（ホーム上部の骨組みは900px）のwebpにして `art/g1〜g6.webp`・`hero-frame.webp` に配置。ホーム上部は「空(art/hero-sky)→骨組み(右と下を見切れ)→波型SVGで本文につなぐ」の3層、今週の報告カードは木目(art/report-wood)の上に写真。空と木目はダークモードでは非表示（白部分が灰色のもやになるため）。差し替えるときは同じ名前で置き、`?v=` と `service-worker.js` の `APP_SHELL`・`CACHE_VERSION` を上げる
- GPTのモック画像・元アイコンは `現場訪問マニュアルアプリ/design/`（git外）

## GPTモック案に寄せる進め方
1. MVPの画面をiPhoneでスクショ（①ホーム ②現場 ③撮影直後 ④報告まとめ）
2. 下のテンプレでGPTにモック案を依頼
3. モック画像を `design/` に置いてClaudeに渡す → まず `style.css` 先頭のデザイントークン（色・角丸・余白・文字）を合わせ、次に部品単位（`.siteCard` `.processCard` `.photoCell` 等）で寄せる
4. イラスト・アイコン類は、GPTに**最初から透過PNGで**出してもらう（走行距離で白フチ処理に苦労した教訓）
