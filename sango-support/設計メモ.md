# 山郷サポート 設計メモ

## 位置づけ
- 現地リーダー向け（2〜3人）。本筋は ①建物から業者の連絡先を調べて電話 ②トラブルと対応を写真付きでナレッジとして残す。報告の主な経路はLINEでリーダーへ、アプリは補助
- 管理者（1〜2人）は記録を一覧・整理する別アプリ（未着手。現場ナビの見守り方式：Box Driveのフォルダを読む）
- 記録は各自の端末内だけ。共有は管理者画面で行う（リーダーは自分の記録のみ見られる）。金額は管理者側で後から入れる
- 過去履歴（旧sango_afterの78件）は管理者側のみ

## 構成（現場ナビと同じ考え）
- サーバーなしのPWA（vanilla JS）。IndexedDB `sango-support`（meta / records / photos=サムネ付き情報 / images=画像本体）、localStorage `sango-support-*`
- **社内データはアプリ（git・公開先）に載せない**。建物・カテゴリ・業者・電話・本社連絡先は「マスターパック」JSON（kind `sango-support-master`、schema 1）で配布 → 設定から取り込み
  - 作り方：`RAG（ナレッジ）/sango_after_ver2/tools/build_master.py`（`csv/vendor_master_grid.csv` ＋ `csv/vendor_phones.csv`＝業者ごとの電話・担当 ＋ `tools/master_settings.json`＝本社電話）→ `master_pack/マスター_<日付>.json`。電話番号は会社ごと15行ほどを記入すればよい
- 「困ったときは」：マスターパックの `help`（title・lead・contacts[name,phone]）をホーム上部に大きく、建物ページに小さく表示。社名はパック側にだけ持つ。電話はタップで確認シート→発信
- 画面（2026-10-04 v12で再構成）：ホーム（建物一覧）→ 建物ページ（12の分類）→ **分類ページ（①何が起きたかを書く ②連絡先 ③この分類の症例＝履歴は下にたまる）** → 症例入力（保存直後に「管理者へ報告しますか？」）。言葉は「記録」でなく「症例」「報告」。下タブは ホーム／自分の記録。設定は右上の歯車
- ルーティングは `#/home` `#/b/<建物id>` `#/new?b=&c=&id=` `#/mine` `#/r/<id>` `#/settings`
- 管理者へ送る：`navigator.share` でJSON（kind `sango-support-records`、schema 1）＋写真を共有シートへ（Box宛メール）。宛先は設定、または app.js の `BOX_UPLOAD_EMAIL`（Boxの受け取りフォルダは未決）
- 絵は `art/` に置く。無い時は仮の絵（建物＝簡易イラスト、カテゴリ＝漢字1字）で動く。ファイル名：建物 `bld-<id>.webp`（id：haru kou wa chi u larch haruka botanical kumajirushi reception larch-back gaiko）、カテゴリ `cat-01.webp`〜`cat-12.webp`、`logo.webp`、`hero.webp`。差し替えたら `?v=` と service-worker.js の CACHE_VERSION を上げる

## 症例の状態（2026-10-05 v17）
- 3つの状態：**未報告 → 報告済み（管理者へ送った）→ 完了（現場で解決した）**。一覧では 報告済み＝薄く、完了＝さらに薄く表示。詳細に「完了にする（解決した）／対応中に戻す」ボタン。自分の症例のフィルターは すべて／未報告／報告済み／完了／下書き
- 報告JSONに `done_at`（完了日、無ければ空）を載せる。完了にしたあと管理者にも伝えるには、もう一度「管理者へ報告する」（管理者ビューアの詳細・CSVに「現場の状況：完了◯/◯／対応中」として出る）
- 編集しても完了は消えない。報告のあと編集すると未報告に戻る（再報告が必要）
- 写真：「カメラで撮る」「撮影済みを選ぶ」。撮影日時は縮小前にEXIF(DateTimeOriginal)から読む（現場ナビと同じ）。アドレスのコピーは設定・報告画面にボタン、「メールを開く」を押した時にも自動コピー

## 「LINEで連絡する」（2026-10-05 v18）
- 報告は2種類：**管理者に報告する**＝メールでBoxへ（管理ページに載る）／**LINEで連絡する**＝LINEに文章＋写真（管理ページには載らない。受け取った人が「症例を書く」で登録し直す）。報告画面（保存直後・詳細）に2つのボタンを並べ、違いを小さい説明で出す
- LINEは共有画面（`navigator.share({text, files})`）に文章と写真（JPEGのみ、JSONは付けない）を渡す。**LINEが文章・写真のどちらかしか受け取らない場合があるため**、「文章だけ／写真だけ」ボタンも用意（実機で要確認）。押した瞬間に文章をクリップボードにもコピーする
- 状態：LINEで送って「送れた」と答えると `lineAt` を記録し、症例に「LINE連絡済み」の印（水色）。報告状態は未報告のまま（管理者に報告したら報告済み）。編集しても印は残る
- 文面：`【症例】建物／分類　日付`／何が起きた／対応／対応した業者／連絡元（報告した人）／連絡した人／（写真N枚）／「管理ページには未登録」の注意書き

## 報告の送り方：窓口（GAS）へ自動送信（2026-10-05 v20）
- 「管理者に報告する」＝ボタン1つで、症例（`submit`）と写真（`putPhoto`、3枚ずつ並行）を**GAS窓口**へ送る。成功したら報告済み。失敗（電波・窓口の不具合）した時は、症例は端末に残り、「もう一度送る」か「メールで送る（予備）」（従来の共有画面→Box）を選べる。詳細にも「メールで送る（予備）」の入口あり
- 窓口のURLと**送信用の合言葉**は、マスターパックの `api: {url, token}` で配る（公開リポジトリには入れない）。`api` が無い（古いパック）時は、従来どおりメール送信。設定の「報告の送り方」で「つながるか確認」（ping）
- 送信用の合言葉は**症例を足すだけ**で、読めない（管理用の合言葉は管理者ビューアだけ）。通信は `fetch`（POST、Content-Type: text/plain、リダイレクト追従）
- 窓口の作り・コード・合言葉は社内側 `RAG（ナレッジ）/sango_after_ver2/gas/`（git外）

## 対応の依頼（2026-10-08 v23）
- 症例の入力で「報告のみ」か「対応を依頼する」（＋急ぎ）を選べる。依頼は一覧・詳細に「依頼」「急ぎ」のタグが付き、送るボタンも「依頼を送る（本社に連絡）」になる。
- 窓口は、依頼を受け取った最初の1回だけ、本社（設定したメール宛）にメールする。送るデータに `kind`（request）と `urgent` を含める。

## 点検・メンテナンス（2026-10-11 v24、inspect.js）
- 下のタブに「点検」（窓口につながっている時だけ）。窓口の `inspectList` から、項目マスターと**全リーダーの記録**を読む（リーダー同士で二重チェックにならない）。自分の記録は、端末（IndexedDBのmeta：`insp`＝控え、`inspPending`＝送信待ち）に保存してから、写真→`inspectSubmit` の順に送る。電波がなければ、次に開いた時や online になった時に自動で送る。
- 期限：周期 `months`（前回の実施日＋n か月）と `season`（毎年この月の末日。前回が入っていた期限の、次の期限）。記録がない項目は「まだ記録がありません」（期限は出さない）。記録を取る単位は 項目×建物。
- 種類：`check`＝点検表（○／要対応／対象外、メモ・写真）、`record`＝有資格者が行う法定点検の実施記録（実施日・業者・結果・報告書の写真）。要対応があれば「症例・依頼にする」で、建物・分類（INSP_CAT）・内容が入った症例の入力へ進む。
- 入口：ホームに「期限が過ぎている点検がN件」の帯、建物ページに「点検・メンテナンス」のカード。アイコンは `art/insp-<icon>.webp`（無い時は分類の漢字1字を表示）。
- 項目の元データは `RAG（ナレッジ）/sango_after_ver2/tools/build_inspection.py` → `admin_pack/点検項目.json` → `gas/import_inspections.js` で窓口へ。

## 合言葉（人ごと）・業者データの自動受け取り・質問要望（2026-10-12 v25、login.js）
- 窓口のURL（`API_URL`）はアプリに入っている（合言葉が無ければ使えない）。設定か最初の画面で「合言葉」（人ごと。苗字で登録）を入れると、窓口が `whoami` で苗字・役割を返し、`masterInfo`／`masterGet` で業者データを受け取る。以後、アプリを開いた時（と、戻ってきた時。10分おき）に版を確かめ、新しければ自動で入れ替える。Boxのファイルや共有シートは使わない（「ファイルから取り込む」は予備として残す）。
- 合言葉があると、報告の失敗時の「メールで送る（予備）」と、設定の送り先アドレスは出さない。古い業者データに入っていた共通の送り先（`master.api`）は、合言葉が無い時だけ使う（移行用）。
- 合言葉が止められた・出し直された時は、`tokenBad` を立てて、設定に案内を出す。質問・要望は `feedback`（窓口のシート feedback に残り、木村さんにメール）。
- 苗字は、合言葉で決まる（変更不可）。下の名前は、任意で入力（端末内。同じ苗字の人の区別用）。

## 使い方ガイドと初回の案内（2026-10-12 v26、guide.js。現場ナビと同じ形）
- ヘッダーの「？」→ `#/help`（使い方のページ：はじめに／連絡先／症例・依頼・報告／自分の症例／点検／困った時。「画面で案内を見る」「質問・要望を送る」「開くたびに案内を出す」）。設定にも入口。
- 案内（チュートリアル）：吹き出しで場所を照らす。照らした所は、そのまま押せる（オーバーレイは操作を止めない）。手順は `TOUR_STEPS`（goto＝始まる時に開く画面、target＝照らす場所）。場所が見つからない手順（点検タブが無い等）は飛ばす。固定位置の要素は `offsetParent` が無いので、`getClientRects` で見分ける。初回（合言葉を入れた直後・起動時）に自動で始まり、`tour-done` を保存。`tour-always`＝開くたびに出す。
- 機能を足したら、`TOUR_STEPS`（必要なら）・`viewHelp` の文章・お知らせ（ANNOUNCEMENTS）を更新する。

## 年間予定（2026-10-12 v28）
- 点検タブの上に「期限の一覧｜年間予定」。年間予定は、毎月のものを1行にまとめ、今月から12か月分、月ごとに「何をやるか」（建物・法定の印・その月の記録の進み具合「済 2/5」）を出す。項目を押すと、その項目だけを一覧で見られる。
- 元データは項目マスターの `plan`（標準の予定月）。`tools/build_inspection.py` の `PLAN` で上書き（毎月＝全月、3か月＝1・4・7・10月、6か月＝5・11月、1年＝4月が既定。季節の項目は周期の月）。実際の期限は、前回の実施日から計算するので、予定月とずれることがある。来年以降の期限は、年も表示する。

## 予定月が期限を決める・更新ボタン（2026-10-12 v29）
- 期限の計算：項目の「予定月」（`plan`）が12か月未満なら、前回の実施を含む予定月の、次の予定月の末日。12か月（毎月）なら、前回＋1か月。予定月は、山郷の管理者が管理者ビューアで変えられる（窓口の「点検予定月」シートに別に保存。項目マスターを入れ直しても残る）。窓口が、項目に重ねて返す（`plan`＝今の予定月、`plan_default`＝標準、`plan_custom`＝変更済みか）。窓口の毎朝のお知らせメールも、同じ計算。
- 設定の一番上に「更新」：「データを最新にする」（業者データ・点検）と「アプリ本体を最新にする」（SWとキャッシュを消して読み直し。症例・設定・合言葉は端末に残る）。

## 敷地マップ・点検のいまやること・手配の状況（2026-10-12〜13 v31〜v35）
- **敷地マップ**：ホームの上（`sitemap.js` の `smRender`）。狭い画面（リーダーは常に）は、北・中央・東のエリア→拡大→建物→建物のページ。マップに無い建物は、下の「名前から選ぶ」。公式の図は春と香が逆なので、`art/sitemap.svg` は入れ替え済み。
- **点検の最初の画面＝「いまやること」**（`inspNowHtml`）：期限超過・今月の行を、頻度（毎月・3か月・半年・年1回・季節）ごと→項目ごとに、建物のチップ（赤＝超過、黄土＝今月）で並べる。記録のないものは、下の折りたたみ。「期限の一覧」「年間予定」にも切り替え。
- **手配の状況**（`reqStatusHtml`／`fillReqStatus`）：「対応を依頼する」で報告した症例の詳細に出る。窓口 `requestStatus`（cap=submit）から、段階・訪問予定日・ひとこと・業者の金額の目安だけを受け取る（手配先・粗利を乗せた請求額は返ってこない）。
- お知らせ（ベル）は「新機能」「修正・改善」のタブ。使い方ページ・案内（吹き出し）も、上の内容に更新済み（v35）。
- 見た目（style.css）を変えたら、index.html と service-worker.js の `style.css?v=` も上げる（上げ忘れると、端末が古い設定を使う）。
