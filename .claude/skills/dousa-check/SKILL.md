# 動作チェック

昼は木村さんが `test1` で起こして「動作チェックして」と言う。夜はクラウドの定期実行で動く。やることは同じ。
**軽く済ませる**（利用枠を木村さんの普段の作業と分け合っているため）。ファイルを広く読み回らない。

## 守ること

- **main に直接 push しない。** main は GitHub Pages で、push した瞬間に現場の iPhone に届く。
- **アプリ本体（`genba-manual/` `genba-viewer/` など）は、チェックの中では直さない。** 直す案は下の「直す案の出し方」で別の枝に。
- **本物のデータを書かない。** このリポジトリは公開。報告に現場名・お客様名・人の名前・合言葉・メールアドレスを書かない（テストの作りものの名前はよい）。
- 本物の GAS・Box には何も送らない（テストは偽物の GAS で動く。`tests/README.md`）。

## 手順

コマンドは **最初に1回 `cd tests` してから、1つずつ**動かす（`&&` や `;` でつながない。つなぐと毎回「許可しますか」が出る）。
決まったコマンド（`.claude/settings.json` に書いたもの）は聞かずに通る。

1. 準備（`tests` フォルダで）
   - `node_modules` が無ければ `npm install`。
   - クラウド（Chrome が入っていない所）では、テストに `TEST_BROWSER=chromium` を付ける。ブラウザのダウンロード（`npx playwright install`）はしない（クラウドは外に出られず失敗する。最初から入っている `/opt/pw-browsers` の Chromium を設定が自動で使う）。
2. 前回からの変更を見る
   - `node tools/check-report.js last` → 前回チェックした時のコミット（空なら初回）。
   - `git log --oneline <前回>..HEAD` と `git diff --stat <前回>..HEAD`。
   - **夜で、変更が `tests/` 以外に無ければ**、テストは動かさず「変更なし」の報告だけ置いて終わる。昼はいつも動かす。
3. テストを動かす：`npx playwright test` → `node tools/summarize.js`
4. 落ちたテストがあれば
   - summarize の出力と、関係するアプリの所だけを読んで、原因の見当をつける（どのコミットで、何が変わったから、か）。
   - テストの方が古いだけ（アプリの仕様を変えた）なら、そう書く。テストの書き直しは昼に木村さんに聞いてから。
5. 変更の中身を軽く見る（`git diff <前回>..HEAD -- genba-manual genba-viewer` のうち、目に付く所だけ）
   - 機能を足した・直したのに `ANNOUNCEMENTS` が増えていない
   - 版数（`APP_VERSION`・`?v=`・`APP_SHELL`・`CACHE_VERSION`）の上げ忘れ（テストでも見ている）
   - 消し忘れの `console.log`、書きかけ、明らかな打ち間違い
6. 報告を書いて置く
   - 下の「報告の形」で、`tests/test-results/report.md` に書く（ファイルを書く道具で。`cat <<EOF` は使わない。このフォルダは git に入らない）。
   - `node tools/check-report.js save test-results/report.md 昼`（夜は `夜`）
7. 昼は、画面に報告の要点を3〜5行で出して終わる。

## 報告の形

```
# 動作チェック 2026-10-29 12:30（昼）

- 見た範囲：abc1234..def5678（コミット 3 件）／前回が無ければ「初回」
- テスト：10 本中 10 本通過（20 秒）

## 判断待ち
（下の合格基準を全部満たした「直す案」だけ。無ければ「なし」）
- 枝 `fix/…`：何が起きていたか／どう直したか／足したテスト

## 保留（N 件）
- 合格基準を満たさなかった案・原因が分からなかった不具合を1行ずつ

## 気づいたこと
- 落ちたテスト・ANNOUNCEMENTS の書き忘れなど。無ければ「なし」
```

## 直す案の出し方（夜だけ。昼は木村さんに聞いてから）

- 枝は `fix/<短い英語>` で main から切る。PR は「案」として作るだけ（マージしない）。
- **合格基準**（全部満たしたものだけ「判断待ち」。1つでも欠けたら案は出さずに「保留」に1行）
  1. テストが全部通る
  2. 直した不具合を再現するテストを足してある（直す前は落ちる、を確かめた）
  3. 版数・お知らせを上げてある（`APP_VERSION`・`index.html` の `?v=`・`APP_SHELL`・`CACHE_VERSION`・`ANNOUNCEMENTS` の先頭）
  4. 触ってはいけない所に触れていない：報告やデータの形（schema・JSON の項目）、Box・GAS とのやりとり、合言葉・`BOX_UPLOAD_EMAIL`、`.gitignore`、他のアプリのフォルダ
  5. 小さい：不具合1つに1つの枝、アプリの変更はおおむね 30 行まで
- 1晩に出す案は2つまで。
